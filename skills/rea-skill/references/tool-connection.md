# 工具接入与故障边界

## 先查现状

Skill 是指引，不是 MCP 服务或安装器。只检查当前任务需要的可执行文件、版本和会话工具列表，不扫描无关目录或读取凭据/敏感配置。

REA 已有工具时直接发现其真实 schema 并执行获准分析，不每次重新 setup。工具缺失时先区分：

| 阻碍 | 应对 |
| --- | --- |
| Skill 已安装但无 REA 工具 | 核对当前会话可见列表，说明 Skill 与服务的区别 |
| CLI 在 PATH 不可见 | 核对用户提供的安装路径/当前终端；不自动重装 |
| 服务已注册但当前会话未连接 | 说明可能需要重连/重启；不能凭配置存在宣称已连接 |
| 缺少 JDK/JADX/原生 provider | 只影响需要它的路线，列缺项并继续可做的静态清单 |
| 客户端权限拒绝 | 按实际权限流程处理，不换工具绕过 |
| 版本不支持命令/参数 | 查本机 help 和对应版本文档，不凭 main 文档假定 |

有已安装 `rea` 时先用其 help/版本信息。需要 readiness 时使用该版本支持的诊断；诊断可能写日志或缓存，先说明。缺少 CLI 不代表必须安装 REA，已有 JADX/Apktool/Ghidra 等可以独立完成对应工作。

## 确需安装或注册时

先展示：来源、拟固定版本、下载/执行行为、写入目录、配置与 Skill 替换范围、备份及重连需求。得到相应授权后才操作。

`npx` 即使运行 doctor 或 setup 的 dry-run，也可能下载包并写 npm 缓存，不能当作无副作用的只读命令。不要为了诊断默认运行 `npx ...@latest`。

参考上游 setup 工作流时，把经核对的固定版本代入，并核对该版本 help；用户确认后才实际执行。setup 可能安装上游同名工作流，但本仓库 `rea-skill` 是独立入口，不自动被它替换或安装。

REA 不等于已安装分析引擎；JDK、JADX、Apktool、Android SDK/adb、Ghidra、IDA、Hopper 逐个核对。商业工具需用户合法获得并授权使用，不提供激活绕过。

## 执行与停止

- 未知 EXE、DLL、JAR、脚本与解析目标放隔离分析环境；校验哈希只能确认文件一致性，不证明安全。
- 每次分析设有限时间、内存/输出预算；保存失败与部分结果，不输出无限日志到对话。
- 清理只针对本任务创建的进程/会话；若工具报告残留或无法确认清理，先停止此 provider，保留位置与诊断。
- 不自动更新或重装以解决未知失败。先用一个最小样本/操作定位阻碍，再提出精确修复范围。

工具就绪检查成功只说明前提条件通过，不代表目标已成功分析；分析成功也不代表目标实际行为已验证。
