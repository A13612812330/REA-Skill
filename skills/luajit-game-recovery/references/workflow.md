# 通用流程与质量判断

## 1. 识别输入

记录输入绝对路径、文件大小、SHA-256、操作系统和位数。只读列出已授权安装目录的文件，检查 PE、附加区、归档标记和运行库证据。不要为识别包而直接启动未知 EXE。

LÖVE 包可能是独立 `.love` ZIP、融合于启动器的 ZIP，或自定义容器。LuaJIT 字节码以十六进制 `1b 4c 4a` 开头；普通 Lua 的 `1b 4c 75 61` 应走另一条工具路线。版本与兼容性还需结合头部 flags、运行库及解析器结果确定，不能仅凭一个字节判定所有变体。

若发现 Unity、Unreal、Godot 或其他引擎，停止套用本 Skill 的提取和 LuaJIT 命令，向用户报告证据并改选相应方法。

## 2. 分离容器与脚本问题

归档可直接读取时优先用标准解析器。自定义封装先检查加载器如何定位内容、验证长度与完整性；把格式描述、输入哈希和适配代码一起保存。不要因为某游戏用过 AES-GCM 就假定其他游戏也相同。

提取前验证目标绝对路径仍在输出目录内，拒绝路径穿越、符号链接、重复路径及已有目标，限制解压总大小。保存逐文件大小、SHA-256、类型及原始相对路径。认证、解压或校验失败时保留失败记录，不继续宣称提取完成。

原始文件只读保存；将目录划分为 `extracted/`、`bytecode-disassembly/`、原始反编译输出、`recovered-source/`、`data/`、`preview/` 和 `analysis/`，或使用项目已有的对应目录。

## 3. 恢复 LuaJIT 文本

选择匹配字节码的现成工具，固定发布版/提交并验证下载文件哈希；先用少量脚本试跑再批量运行。记录每个输入的返回码、超时、输出与错误，既检查数量也检查路径集合，不能只看进程退出码。

本次案例使用的工具：

- `marsinator358/luajit-decompiler-v2`：恢复可读文本。
- `Dr-MTN/luajit-decompiler`：原字节码解析、常量提取和反汇编；其旧文本结果不优先于已验证的新结果。
- Tree-sitter Lua：必要时定位生成代码的语法结构，不用全文正则盲改绑定关系。

上游入口：

- https://github.com/marsinator358/luajit-decompiler-v2
- https://github.com/Dr-MTN/luajit-decompiler
- https://github.com/love2d/love/tree/main/src/modules/filesystem

这些地址用于核对来源，不代表自动下载或执行授权。不要将上游当前默认分支当作本次样本已验证的版本。

### 常见失败

| 现象 | 处理 |
| --- | --- |
| `.lua` 无法按 UTF-8 读取 | 检查文件头，可能仍是字节码 |
| Windows 中文路径失败 | 用 ASCII 相对参数和合适工作目录；保留原中文文件位置，不默认移动项目 |
| 工具断言弹框 | 使用其已核实的静默选项，并记录跳过文件；静默不是成功 |
| BOM 导致编译失败 | 在恢复副本处理 BOM，不修改原始产物 |
| 局部变量超过编译器限制 | 保留失败输出，基于 AST 分析绑定、遮蔽、闭包和循环生命周期后窄修 |
| native 编译器崩溃 | 每文件独立子进程，限制超时，保存返回码；不能让同进程状态污染后续报告 |

将生成局部变量提升到表字段可能改变语义。Slotbound 的 8 文件修正清单和阈值只对该样本适用；其他程序需重新确认作用域、重名、递归、闭包捕获及 `nil` 初始化。语法通过仍需行为测试。

## 4. 导出数据与资源

优先静态导出原字节码中的字符串、数值、常量表、函数原型与指令。标注其不是完整运行时状态，不凭相邻常量猜测单位归属。

确需模块求值时，只对已审查的模块执行，使用独立受限 VM；不开放 `io`、`os`、`package`、FFI 和文件加载入口。为依赖替身、函数类型标记及循环引用标记提供说明。此方法仍可能遇到无限循环、内存耗尽或原生漏洞，不能用于不可信输入的安全保证。

资源导出保留原文件和来源路径，另生成便于浏览的索引/缩略图。PNG 文件校验不代表画面或动画正确；音频计数不代表全部解码成功。语言 JSON 要实际解析；中文条目数不等于有效技能数量。

## 5. 验证与 Mod 交接

使用匹配运行库逐文件编译恢复文本，但不执行游戏。数据模块在原字节码与恢复文本的独立 VM 中分别求值；针对纯函数设计正常值、边界值和异常输入对照。记录被跳过模块及原因。

若比较时把函数替换成类型标记，只能证明返回表中的可比较数据一致；闭包和技能逻辑不能因此判定一致。保留测试输入、输出、误差规则和覆盖范围。

可玩验证应另建运行副本并确认范围，不覆盖原安装。先验证一项小改动及回滚方式，再测试整局、技能、音画和存档兼容。提取成功不能证明发行包接受修改后的内容。

发布前核对 Git 工作区、第三方许可与材料范围，排除游戏运行程序、存档、依赖缓存、凭据和私人路径泄漏。授权个人研究不等于允许公开再分发第三方代码与资源。
