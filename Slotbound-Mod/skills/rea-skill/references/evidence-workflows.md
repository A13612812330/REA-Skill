# 证据、功能追踪与验证

## 先回答问题再扩大范围

把任务分成可回答的问题，例如“这个数值从哪里来”“按钮调用哪个算法”“某资源如何加载”。为每个问题选一个入口，追踪：

`输入 -> 事件/路由 -> 调用 -> 核心计算 -> 配置/状态 -> 输出/副作用`

按疑点批量查相关函数、字符串和引用，不全局盲搜到结论。静态引用不证明运行时可达；反射、虚表、JNI、脚本桥和动态加载可能留下未知边。

## 记录格式

可用项目已有格式；没有时使用简洁 ledger：

| ID | 问题/结论 | 状态 | 输入与位置 | 工具/命令及证据 | 覆盖与限制 | 下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| F001 | 待填实际问题 | open | 实际样本 SHA-256 与路径 | 实际日志或 Evidence ID | 尚未分析 | 最小验证动作 |

状态含义：

- `observed`：在指定文件/输出中实际观察到。
- `documented`：来自说明资料，未独立验证。
- `inferred`：有依据的推断，列出替代解释。
- `runtime-verified`：在注明输入、环境、动作和时间范围的执行中验证。
- `open`：证据不足或工具受限；搜索没找到不是不存在。

每次执行保留输入哈希、工具版本/来源、参数、输出位置、返回码与超时。输出文件的来源可追到原路径/成员、地址/RVA、DEX 类与描述符、资源 ID 或抓包记录编号；工具重命名后的别名与原始身份分开记。

## 摘要和分页

若 REA 支持 retained Evidence，先取得摘要，保存 parent Evidence ID，再按其接口选 facet、节点或稳定分页。完整记录与摘要不是同一个结果，不丢失原始 ID。

客户端截断、工具截断、搜索分页和来源不完整是不同限制。跟随工具实际返回的 next offset/cursor，并核对摘要身份和样本哈希；页耗尽不意味着包内功能、间接调用或网络记录完整。没有 retention 时保存完整输出到获准路径，不把截断预览当可解析的完整 JSON。

失败时保留已有部分证据。只有参数、输入、工具状态或明确阻碍改变后才重试，不重复生产相同的大结果。

## 验证分层

1. 提取：认证/长度/清单/哈希与路径检查。
2. 表达：反编译文件集合、失败列表、逐文件语法或结构检查。
3. 数据：静态值与执行求值分开；依赖替身、函数占位、循环引用明确记录。
4. 语义：原始实现与重建实现用相同输入分别运行，对照输出、异常、精度和状态副作用，覆盖边界与反例。
5. 端到端：独立副本或测试设备中实测特定工作流；不从小样本外推全部功能或存档兼容。

对照执行遵循当前权限和隔离要求。超时、OOM、无法执行或缺失输出均不能算匹配。语法成功不能填为行为成功；函数占位的表比较不能填为函数等价。

## 交付

产物按需要分成原始输入索引、提取文件、反汇编、未修正反编译、恢复/重建文本、数值/资源索引、运行日志和报告。已有项目目录就沿用，不为了模板搬动原产物。

中文报告回答：分析哪个版本；用户问题回答到哪里；主要结论和证据；具体文件位置；已执行检查与失败项；仍需验证内容；下一步最小动作。所有计数注明对象与范围。

功能重建放独立目录，注明基于哪些行为证据以及哪些属于新设计。不得标成原始源码或掩盖人工补全。

发布只覆盖用户允许的产物。审查第三方许可、账户信息、凭据、设备标识和个人路径，核对 Git 根、工作区与暂存清单，推送后核对远端提交和文件。分析授权不自动包含公开上传。
