# REA-Skill

以用户的问题为目标，用发行物和明确范围的运行证据解释实现，交付可检查的代码、数值、资源和分析报告。反编译文本、伪代码、重建实现与开发者原始源码必须分开标注。

这是统一工作流，不是新的反编译引擎。已完整纳入旧 `luajit-game-recovery` 的流程、Slotbound 适配、只读预检和回归测试；本目录不依赖旧 Skill 目录。其他路线提供分析方法和工具选择，不代表相应工具已经安装或在当前主机验证。

## 接收任务

先读 [口语调用与信息补全](references/task-intake.md)。用户说“我需要反编译”“帮我逆向 XXX”等，不要求其知道 Skill 名；先提供待补充模板和拟执行流程，等用户补充并确认本目标范围后才分析。

从当前对话填入已知应用、文件、研究目标和输出目录，不重复索取已知信息，不将示例路径或旧项目当成新目标。仅提供路径/补充字段不等于执行授权；用户信息齐全且明确“按此开始”后再执行。已批准目标的同范围续作沿用确认，不反复填表；新目标或扩大范围再确认。

确认前只读 Skill 与既有上下文，不读取目标内容、不创建分析目录、不运行解析器/反编译器或安装工具，也不连接设备。

默认静态只读识别；产物写入独立项目目录，不改原包、安装目录、存档或设备。区分本地文件分析、目标执行、设备连接、网络访问、修改重打包和远程发布的授权。不要从其中一种推导其他操作已获允许。

新项目按用户当前确认规则执行。没有指定目录时提出独立分析目录建议，不把新目标写入旧案例。REA-Skill 是通用工作流主体；本仓库的 `cases/slotbound-demo/` 是独立案例子项目，不是所有分析的默认输出目录。新增案例的归档与发布另行确认。

## 调查流程

1. **绑定样本。** 记录绝对路径、大小、SHA-256、包/架构/运行时证据和可用工具。扩展名、文件名或目录邻近关系只能作线索。先清单与摘要，再深入具体问题。
2. **选择入口。** 从用户指定功能的页面、类、字符串、资源 ID、导出函数或协议字段出发，追踪输入、分发、核心计算、依赖、状态与输出。不要用全量反编译替代功能定位。
3. **最小工具集。** 优先已可用的现成解析器、反编译器或 MCP。按真实工具列表和 schema 调用；本 Skill 中的工具名只是经核对的参考，不能假装工具可用。REA 未接入时仍可用已有独立工具继续。
4. **保留原始证据。** 原文件、字节码、汇编、原始反编译、人工修正、数值导出和预览分目录保存。绑定工具版本、参数、输入、输出、返回码、超时与失败列表。
5. **围绕疑点扩展。** 先用摘要、已有 Evidence 和稳定分页；保留覆盖范围和截断标记。无新输入或环境变化时不重复相同失败调用。确需动态验证时先明确设备/进程、动作、网络和可见副作用，再在隔离环境按范围执行。
6. **逐层验证。** 文件可读取、文本可编译、数据一致、函数用例一致、完整功能实测是不同结论。对照具体输入输出，保留反例和未验证内容。重建实现另存，不能覆盖证据文件。
7. **回答原问题。** 交付路径图、主要结论及证据、覆盖/失败范围、未知项和最小下一步。工具未安装、输出不完整或失败时报告部分结果，不宣称完整恢复。

归档提取须检查路径穿越、链接、重复/大小写冲突和展开大小上限，并拒绝覆盖已有输出。未知解析器和目标代码应在隔离环境处理；裁剪标准库、JVM 或独立进程不等于安全沙箱。

运行时只清理本次拥有的进程、会话和工作空间，不关闭用户已有调试器。超时、资源耗尽或无法确认清理时暂停该执行路线，保留诊断并说明阻碍，不靠无限重试或删除校验制造成功。

## LuaJIT 完整继承

保留包识别与认证提取、字节码反汇编/常量导出、Lua 文本恢复、AST 局部变量整理、数值 JSON/CSV、图片预览/索引、资源清单、逐文件语法检查和选定纯函数对照的方法。

以下预检仅针对本仓库 Slotbound 交付材料，不是通用 APK/EXE 扫描器：

```powershell
python "<rea-skill目录>/scripts/preflight.py" --project "<REA-Skill仓库>/cases/slotbound-demo"
python "<rea-skill目录>/scripts/preflight.py" --project "<REA-Skill仓库>/cases/slotbound-demo" --exe "<已授权的Slotbound.exe>"
```

预检的 `--project` 指向案例根目录，不是仓库根目录。预检只用 Python 标准库，不写文件、不加载 DLL、不执行游戏或反编译器。退出码 0 为检查通过、1 为失败、2 为参数错误。它检查已存报告与路径集合，不重新验证语法或源码内容；未传 `--exe` 就没有核对游戏版本。完整重放依赖案例内 `tools/` 和可信运行库，不随 Skill 目录分发。

Slotbound 适配必须匹配文档中的 EXE 哈希。不能将它的密钥定位、偏移、容器格式或 8 文件 AST 修正规则套用其他样本；哈希不匹配时停止专用流程，重新识别。

## 能力与发布边界

- 原生程序通常得到汇编与伪代码；APK 的 DEX 恢复文本不等于原 Kotlin/Java 工程；IPA 不意味着可恢复完整 Swift 工程。客户端包不能提供未随包分发的服务端源码。
- 混淆重命名不恢复原始语义；字符串中的地址不证明当前服务可用，也不授权访问它。
- 模块求值、动态加载、设备安装、调试、注入、重签名和可玩 Mod 验证不是静态分析，按当前授权单独处理。不得为获取更多结果擅自移除认证或完整性校验。
- 不读取凭据、私钥、签名密钥或私人账户数据；意外发现时报告类别和位置，不输出或上传值。
- 安装本 Skill 不会安装 REA、JDK、JADX、Apktool、Ghidra、IDA 或 MCP。下载、执行安装器、改变配置和发布分析产物先核对范围；私人研究不等于允许公开分发。

方法来源、固定阅读提交和未验证范围见 [来源与继承关系](references/sources.md)。
